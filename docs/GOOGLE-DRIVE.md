# Google Drive 書庫與分享連結(實驗)

讓使用者用自己的 Google 帳號登入,書庫存在**他自己的 Google Drive**(根目錄的「Leafpile」資料夾),換電腦、用手機都能打開;
也能把一篇筆記、一份簡報、一張畫布產生成連結,對方不用登入就能看。

這一頁是給**架網站的人(維護者)**看的:設定只做一次,所有使用者共用。使用者只會看到「用 Google 登入」。

## 運作方式

- **權限只有 `drive.file`**:Leafpile 只看得到自己建立的檔案,使用者 Drive 裡其他東西完全碰不到。
  這是 Google 歸類的「非敏感」權限,[不需要送審](https://support.google.com/cloud/answer/9110914)。
- **沒有伺服器**:程式在使用者的瀏覽器裡直接呼叫 Google Drive API,筆記不經過任何其他地方。
- **通行證**只存在那個分頁,約一小時過期;過期時會跳出「繼續」請使用者按一下重新連線。
- **分享**:把用到的檔案設成「知道連結的人都能看」,另外寫一份分享清單(`_shared/*.json`,也公開),
  連結是 `…/#/s/<清單的 id>`。對方的瀏覽器用 API 金鑰讀這些公開檔案,沿用原本的筆記、簡報、畫布畫面(唯讀)。
  分享後再改內容,對方看到的也會更新;新增投影片、圖片、卡片要再按一次「分享」(連結不變)。「停止分享」會取消公開。

## 請求量與限速

- Drive API 免費;額度按專案與使用者計算(每人每分鐘 325,000 單位),個人書庫用不完。
- 所有請求都經過 `driveClient`(`app/sources/drive.js`):被限速時(429、原因是限速的 403、5xx)等 1、2、4、8、16 秒(加隨機)再試,最多 5 次;沒有權限的 403 不重試。
- 分享時同時送 4 個請求(`pool`);重新分享只公開新加入的檔案、只取消不再需要的(上次這個分享還在進行中的,與其他分享正在用的,都視為已經公開)。
- 如果你在 Drive 網頁手動取消了某個檔案的共用,Leafpile 不會知道;按「停止分享」再「分享」一次就會全部重設。

## 設定步驟(約 20 分鐘)

Google Cloud 的選單名稱常改,以下是 2026-11 的名稱。

1. 到 [Google Cloud Console](https://console.cloud.google.com/) 建立一個專案(免費),例如 `leafpile`。
2. **啟用 API**:「API 和服務」→「程式庫」→ 搜尋 **Google Drive API** → 啟用。
3. **Google Auth Platform**(舊名「OAuth 同意畫面」)→ 開始設定:
   - 應用程式名稱 `Leafpile`、使用者支援電子郵件、目標對象選 **外部**、聯絡電子郵件。
   - 「資料存取」→ 新增範圍 → 手動輸入 `https://www.googleapis.com/auth/drive.file`。
   - 「目標對象」:先維持 **測試** 狀態,在「測試使用者」加入你自己的 Gmail(最多 100 人)。
     測試狀態下大約每 7 天要重新同意一次;只用非敏感權限時也可以直接「發布應用程式」,不必送審
     (同意畫面會顯示網址而不是 App 名稱,要顯示名稱與圖示才需要「品牌驗證」)。
4. **用戶端**:「用戶端」→ 建立用戶端 → 類型 **網頁應用程式** →「已授權的 JavaScript 來源」加入:
   - `https://torusmith.github.io`(只寫到網域,**不要**加 `/Leafpile` 路徑)
   - 本機測試用:`http://localhost:8765`
   建立後複製 **用戶端 ID**(`….apps.googleusercontent.com`)。網頁應用程式用不到用戶端密鑰。
5. **API 金鑰**(分享連結用):「API 和服務」→「憑證」→ 建立憑證 → API 金鑰 → 編輯:
   - 應用程式限制:**網站**,加入 `https://torusmith.github.io/*`(與 `http://localhost:8765/*`)
   - API 限制:只勾 **Google Drive API**
6. 把兩個值填進 [`app/config.js`](../app/config.js) 的 `fixed`。兩者都不是密碼,可以公開放在 repo:Google 只接受從登記過的網址使用。

想先試、不改程式:在網站上打開瀏覽器主控台(F12),執行下面這行再重新整理,只影響那個瀏覽器:

```js
localStorage.setItem('leafpile-google', JSON.stringify({ clientId: '貼上用戶端 ID', apiKey: '貼上 API 金鑰' }))
```

## 使用

- 首頁「Google Drive(實驗)」→ 登入 → 第一次會建立「Leafpile」資料夾並顯示「用範例開始／只建立空書庫」。
- **把本機的筆記搬上去**:空的 Drive 書庫選「匯入現有書庫」;已經有內容時用書庫頁的「書庫包」→ 匯入。可以選資料夾或 zip,先預覽,**不覆蓋**已經有的檔案,匯入後可以按「復原」。
  一定要經過 Leafpile 匯入(等於由 Leafpile 上傳):直接在 Drive 網頁上傳的檔案,Leafpile 看不到(見下方限制)。
- 分享:筆記右上「更多 ▾」→「分享…」;簡報工具列「⋯」→「分享…」;畫布「更多」→「分享…」。也可以用 Ctrl+K 搜尋「分享」。
- **分享書庫**:書架「分享書庫…」。只公開標成「公開」的筆記與簡報(規則與公開版書庫包相同:簡報跟著主題的 `public`,`local_only` 主題與畫布一律不放)。對方打開是唯讀的書架。改了公開／私人之後再按一次,連結不變;改回私人的會取消公開。
  這也讓「公開／私人」第一次成為真正的權限:Drive 裡沒分享的檔案,別人用任何方法都讀不到。
- 首頁「登出 Google」:清掉這個分頁的通行證。要完全撤銷,到 Google 帳號 →「安全性」→「第三方應用程式」移除 Leafpile。

## 已知限制(原型)

- 只看得到 Leafpile 自己建立的檔案:從 Drive 網頁或電腦版 Google Drive 直接放進「Leafpile」資料夾的**新檔案**看不到,要用上面的「匯入」。用別的 App 修改 Leafpile 建立的檔案則沒問題。
- 自己在 Drive 手動建的「Leafpile」資料夾也看不到,Leafpile 會另外建一個同名的。
- 沒有即時偵測變動;另一台裝置改過的檔案,重新打開書庫才會出現。存檔前一定會向 Drive 確認,不會蓋掉另一台的修改。
- 沒有離線模式、沒有快取:每次打開書庫列一次清單,檔案多時會慢。
- 分享筆記時,圖片只包含以相對路徑引用、在書庫裡的檔案。
- 同一個資料夾裡有同名檔(Drive 允許)時,只用最新的那個。
- 這些都只在模擬的 Drive 上測過(`tests/drive.test.mjs`、`tests/fake-drive.mjs`);真正的 Google 登入要用真的帳號試。
