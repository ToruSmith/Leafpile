# 路線圖

一人加 AI 的估算：約 18 週到 v1.0，第 8 週可以開始自用。**每個階段的閘門沒過，不開下一階段。**

## P0 奠基（第 1–2 週）

- [x] 定位、命名、授權（程式 MIT、內容 CC BY 4.0）
- [x] 存檔規格 `docs/SPEC.md` 與互通規則 `docs/INTEROP.md`
- [x] 預設分類與主題、範例筆記與簡報、範例畫布
- [x] 守門腳本與 CI
- [x] README、貢獻、AI 揭露、安全、行為準則
- [ ] 確認名稱可用（GitHub repo、網域；若發 CLI 再查 npm）
- [ ] 在 Mdslide Pile 補上 LICENSE（MIT）
- [ ] 建立 GitHub repo、開啟 Pages（Source 設成 GitHub Actions）

**閘門：規格凍結 v0**：自己照 SPEC 手動整理一個真實書庫（至少 20 篇筆記、2 份簡報），沒有遇到規格答不出來的情況。

## P1 MVP（第 3–8 週）

- [ ] 把 Mdslide Pile 的 `app/`、`scripts/`、`tests/` 帶進來，全部測試照舊通過
- [ ] `core/note.js`、`core/links.js`、`core/privacy.js` 與單元測試
- [ ] `library.js` 雙渠道掃描與主題配對；自動判斷開啟層級
- [ ] 雙渠道書架（筆記｜簡報｜全部）、分類分組、急件區
- [ ] 筆記閱讀頁（置中單欄、字級、目錄）與編輯模式（沿用 Mdslide 編輯器）
- [ ] `[[連結]]` 與反向連結面板、IndexedDB 索引
- [ ] 快閃播放
- [ ] Ctrl+K 指令面板
- [ ] 中英文介面

**閘門：自用一個月**：每天用它寫筆記，至少一次真的上台報告。

## P2 互通（第 9–12 週）

- [ ] `![[摘錄]]` 嵌入
- [ ] 升級成簡報（介面＋`scripts/promote.mjs`）
- [ ] 講後筆記與講者視窗的問答分頁
- [ ] 檢查工具的互通規則
- [ ] 文件與範例同步

**閘門：公開 Beta**：三位以上外部使用者完成「筆記 → 簡報 → 講後筆記」一輪並回饋。

## P3 擴充（第 13–18 週）

- [ ] 畫布：由 Vault 移植，改寫成 ES 模組，筆記卡與簡報卡
- [ ] 個資掃描介面（發布前檢查、訪客視角預覽）
- [ ] 急件置頂與到期提醒的介面
- [ ] 效能：1,000 篇筆記的書庫，首屏 1 秒內

**閘門：v1.0**

## 之後（選配）

- GitHub API 寫回急件（細粒度權杖，只在使用者的瀏覽器）
- 雲端同步 adapter（例如 Google Drive，沿用 Vault 經驗）
- 手機編輯
