以下是 2026-11-13 參考同類工具（Logseq、Flexnote、AppFlowy、Obsidian 協作外掛）後的評估。只借想法、不搬程式碼（Logseq、AppFlowy 是 AGPL，Flexnote 是商業軟體；Leafpile 是 MIT）。

- 原則不變：檔案就是唯一來源，不加資料庫。Logseq 在 2026 年 4 月因為同時維護檔案版與資料庫版太複雜，拆成兩個 App，印證這個決定
- PDF 劃線變成卡片（Flexnote）：需要 PDF.js，違反零依賴，不做
- 共用資料夾引導：把本機書庫放在 Google 雲端硬碟電腦版、OneDrive 或 Dropbox 的同步資料夾，就能多台電腦使用、分享給別人；檢查工具提醒同步軟體產生的衝突副本（例如 `筆記 (1).md`）。零依賴，建議先做
- Google 雲端硬碟書庫來源（像 Obsidian 的 Google Drive 外掛）：手機也能編輯、直接分享資料夾。需要維護者註冊 Google OAuth 用戶端（只用 `drive.file` 權限）並放寬 CSP；做成 App 上架時再一起評估
- 即時共同編輯（像 Relay、Peerdraft，用 CRDT）：需要中繼伺服器與相依套件，維護成本高，不做
- 分享第 2 級：讀取任何公開 GitHub 倉庫的書庫（`#/gh/帳號/倉庫`），加上發布引導。維護者決定先做到第 1 級（書庫包），因為之後可能做成 App 上架

- GitHub API 寫回急件（細粒度權杖，只在使用者的瀏覽器）
- 雲端同步 adapter（例如 Google Drive，沿用 Vault 經驗）
- 手機編輯
