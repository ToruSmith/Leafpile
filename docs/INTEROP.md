# 筆記與簡報的互通（Leafpile 的特色）

## 一條原則

> **筆記是知識的唯一來源，簡報是一次演出。**

所以：內容可以跨渠道**引用**，也可以**複製一次**；但永遠不**自動雙向同步**。

為什麼不同步：簡報應該比筆記短、比筆記口語、常常重新排順序。雙向同步會讓兩邊互相覆蓋，最後誰都不敢改。

## 五種走法（加上畫布與筆記整理）

由上到下，對檔案的影響越來越大。

### 1. 連結

```markdown
相關：[[兩個渠道]]、[[兩個渠道#一句話]]、[[slides:2026-11-leafpile-tour]]
```

- 筆記與投影片都可以寫。
- 不改任何檔案。
- 筆記閱讀頁右側欄顯示**反向連結**：哪些筆記、哪些簡報連到這篇。簡報只算一個節點（不是每張投影片），避免圖譜被投影片淹沒。

### 2. 快閃播放

筆記右上角 ▶，把筆記暫時拆成投影片播放：

- 拆張規則：有單獨一行的 `---` 就依它拆；否則依 `##` 拆；第一個 `#` 當標題頁。筆記的 `##` 在投影片上顯示成標題。
- 版型全部用 `auto`；front matter 只讀 `title` 與 `date`。
- 不能在播放器裡編輯或檢查（那是暫時的投影片）；要改請回筆記。
- **不產生任何檔案**；可以用畫筆，但畫的內容不會存。
- 適合臨時在會議中分享筆記。要正式上台，請用「升級成簡報」。

### 3. 摘錄嵌入

投影片裡**單獨一行**寫：

```markdown
![[兩個渠道#一句話]]
```

- 播放時讀取那一段筆記（到下一個同級或更高級標題為止），放在投影片上。
- 唯讀：在投影片上不能改它，要改請回筆記。
- 檢查工具：摘錄超過 120 字提醒「簡報應該比筆記短」；找不到段落時報錯。
- 匯出單一 HTML 時，摘錄的內容會一起內嵌（匯出當下的版本）。
- 找不到來源時顯示原本的文字，播放器的提醒會列出來。
- Mdslide Pile 與匯出後離線開啟的舊檔不認得這個語法，會顯示成文字。

### 4. 升級成簡報

在筆記上按「做成簡報」（筆記本裡的筆記可以選擇整本一起升級），或執行 `node scripts/promote.mjs <書庫> <筆記或筆記本的路徑>`：

| 筆記裡 | 變成 |
|---|---|
| `title` 或第一個 `#` | `deck.yml` 的 `title` |
| 長筆記（有 `###`）：每個 `##` | 一個章節資料夾 `01-…/`，底下每個 `###` 一張投影片 |
| 短筆記（沒有 `###`）：每個 `##` | 一張投影片，全部放在同一章 |
| 標題 | 投影片標題（所以筆記的小標請寫結論） |
| 清單、表格、引言、程式碼、圖片 | 留在投影片上 |
| 其餘的說明文字 | 講者備註 `Note:` |

圖片不會自動複製：升級後請把需要的圖放進簡報的 `media/`，檢查工具會列出找不到的素材。

- 新簡報放在 `slides/<同名主題>/<今天日期>-<名稱>/`，`deck.yml` 記錄 `source:`。
- **升級是一次性的複製**，之後兩邊各自獨立。
- 筆記閱讀頁的右側欄會列出「被這些簡報引用」。
- **來源筆記改過的提醒**：升級時 `deck.yml` 會記下 `source_hash`（來源筆記內文的指紋；筆記本則是所有筆記依路徑排序後一起算）。之後來源筆記的內文改過，會在三個地方提醒：開啟簡報時跳出一次提示、筆記右側欄的簡報旁標「筆記已更新」、檢查工具列為警告。
  - 判斷只看內文：front matter（例如改 `tags`、`public`）、換行格式與行尾空白不算改動。不看檔案修改時間，所以 git clone、複製資料夾都不會誤報。
  - 簡報跟上之後：按提醒上的「已跟上，不再提醒」，或 Ctrl+K →「標記簡報已跟上來源筆記」，或 `node scripts/source-sync.mjs <書庫> <簡報的路徑> --mark`。只會改 `source_hash` 這一行。
  - 沒有 `source_hash` 的簡報（手寫的、舊版升級的）不提醒；Ctrl+K →「開始追蹤來源筆記的變動」可以補上。
  - `node scripts/source-sync.mjs <書庫>` 列出所有升級來的簡報與狀態。
- 筆記本升級時，每篇筆記是一個章節，筆記裡的每個 `##` 是一張投影片。
- 目標資料夾已經存在時會停下來，絕不覆蓋。

### 5. 講後筆記

播放簡報時按 Ctrl+K →「把這份簡報存成講後筆記」，或執行 `node scripts/after-talk.mjs <書庫> <簡報的路徑>`：

- 新增 `notes/<同名主題>/<今天日期>-<簡報名稱>-講後.md`。
- 內容：簡報大綱（每章標題、每張標題）、所有講者備註、「現場問答」與留白的「下次要改」。
- **現場問答**：講者視窗（播放時按 S）的「問答」分頁，或在講者視窗按 Q，記下現場的問題（自動帶上當時的頁碼），答案可以之後再補。紀錄存在這台電腦的瀏覽器裡，重新整理不會不見；產生講後筆記時自動帶入，帶入後清空。
  - 唯讀的書庫（例如線上版）不能直接建立筆記：在問答分頁按「下載問答」，再執行 `node scripts/after-talk.mjs <書庫> <簡報的路徑> --qa 問答.json`。
  - `--qa` 也接受手寫的純文字：每題一行 `Q: 問題`（或 `問:`），下一行 `A: 答案`（或 `答:`）。
- front matter 寫 `from_deck:`，`public` 預設 `false`。
- 範例：`content/notes/00-examples/2026-11-leafpile-basics/03-after-the-talk.md`。

### 5.1 匯出與列印裡的 `[[連結]]`

投影片裡的 `[[連結]]` 在播放、匯出的單一 HTML、PDF 裡都不能跳轉（觀眾手上沒有你的書庫）。播放器會把「連到哪裡」寫進滑鼠提示：連到筆記「標題 › 小節」（路徑）、連到簡報「標題」（路徑），或「找不到目標」。這份說明在開啟簡報時用圖譜解析，跟著匯出的單一 HTML 一起帶走，離線開啟也看得到。

### 6. 畫布

`boards/*.canvas`（JSON Canvas 格式，Obsidian 也能開）可以同時放筆記卡與簡報卡，用線表示「升級自」「講後」「相關」。

- 畫布只存位置與連線，不複製內容；卡片顯示時才去讀筆記或簡報的標題。點卡片標題就開啟那篇筆記或那份簡報。
- 從畫布移除卡片（Delete）只改畫布檔，不會動到筆記或簡報。
- 讀寫時保留所有不認得的欄位（包括 Obsidian 與其他工具加的）；Leafpile 自訂的欄位一律 `x-` 開頭。
- 編輯（可寫入的書庫）：拖曳搬動、右下角調整大小、拖曳卡片邊上的圓點連線、雙擊新增文字或編輯、Ctrl+Z 復原。改完 0.8 秒自動存檔；檔案在別的地方被改過就停止自動存檔，不覆蓋。
- 檢查工具：畫布檔壞掉是錯誤；卡片指到不存在的檔案是提醒。
- 選取卡片或連線，上方會出現小工具列：顏色、連線文字、群組名稱、網址、嵌入網頁、允許腳本、轉成筆記、移除。雙擊（或選取後按 Enter）也能編輯。
- **圖片、HTML、PDF**：按「+ 圖片或檔案」、直接拖進畫布，或 Ctrl+V 貼上截圖。圖片自動縮到最長邊 1600 px 並轉成 WebP；檔案存在 `boards/media/`，檔名是內容雜湊（同一張只存一份）。上限：HTML 500 KB、其他 5 MB。從畫布移除卡片不會刪除這些檔案。
- **嵌入**：YouTube、Vimeo、Bilibili、Google 雲端硬碟、Google 簡報（可以直接貼「發布到網路」的整段嵌入碼）會自動嵌入；其他 https 網頁要在卡片上勾「嵌入網頁」（`x-embed: true`）。HTML 檔預設只顯示、不執行腳本，勾「允許執行腳本」（`x-scripts: true`）才在隔離的框架裡執行。所有嵌入一開始只顯示「▶ 載入」，最多同時 3 個；按「互動」才能在卡片裡操作，⛶ 全螢幕，↗ 在新分頁開啟。
- **簡報模式**：「▶ 簡報」依群組一頁一頁放大（沒有群組就逐張卡片，由上到下、由左到右）；←／→、空白鍵或點畫面換頁，Esc 離開。
- **文字卡轉成筆記**：選主題後建立新筆記，卡片原地換成筆記卡，連線不變。筆記頁右側會列出「出現在這些畫布」。

### 7. 筆記的改名、搬移、封存

筆記頁右側「更多 ▾」：

- **改名**：改標題與檔名（保留日期或編號前綴）。front matter 的 `title` 改掉；第一個 `#` 標題和舊標題相同時一起改。
- **搬移**：搬到其他主題或筆記本資料夾。筆記裡相對路徑的圖片與連結會換算成新的相對路徑。
- **連結更新**：先模擬改完之後，每個連到這篇的 `[[連結]]` 還找不找得到同一篇；只改會斷掉或會找錯的。用別名或仍然有效的寫法連過來的不動。改寫時保留 `#小節`、`|顯示文字` 與 `!` 摘錄；優先寫新標題，標題在那個位置會撞名時改寫成路徑。程式碼區塊與行內程式碼裡的不動。
- 簡報 `deck.yml` 的 `source` 指到這篇時，一起改成新路徑（`source_hash` 不變，因為內文沒變）。
- 動手之前會列出所有要改的檔案。先搬筆記本身：寫到新位置、讀回確認一致，才移除舊檔（這是 Leafpile 唯一會移除檔案的地方，內容一定已經在新位置）；新位置已有同名檔案就拒絕。其他檔案改不成功時會列出來。
- **封存**：搬到 `_archive/notes/`（不刪除）。連到它的連結不改，封存前會列出有哪些筆記與簡報連到它，之後「檢查」也會列出。

### 8. 發布前檢查與訪客視角

書庫首頁的「🔒 發布前檢查」（或 Ctrl+K）：

- 統計公開、私人、只留本機的筆記各有幾篇，並列出會公開的筆記（規則見 SPEC 第 6 節）。
- 掃描每篇筆記與每張投影片裡可能的個資：Email、台灣手機號碼、身分證字號。列出在哪篇、第幾行，會公開的排前面；畫面上一律遮罩。只是提醒，不會擋下。範例網域（`example.com` 等）與程式碼區塊不算。
- **訪客視角**：書庫首頁與搜尋只留下會公開的筆記（只留本機主題的簡報也拿掉）；直接打開私人筆記會看到「訪客看不到這篇」。畫面下方的提示條可以隨時結束。

## 刻意不做的事

- **不做雙向同步**：沒有「筆記改了簡報自動改」，也沒有反過來。
- **筆記裡不寫版型**：`layout`、`size`、`background` 只屬於簡報；筆記保持任何 Markdown 軟體都能讀。
- **不把每張投影片放進知識圖譜**：一份簡報在圖譜裡是一個點。
- **不在快閃播放存任何東西**：要存就升級成簡報。
- **不跨渠道搬檔案**：筆記不會「變成」簡報，只會產生新的簡報。

## 檢查工具的互通規則

| 情況 | 等級 |
|---|---|
| `[[連結]]` 找不到目標 | 警告 |
| `[[連結]]` 符合多個目標 | 警告（請改寫成路徑） |
| 投影片裡的 `![[摘錄]]` 找不到筆記或段落 | 錯誤 |
| `![[摘錄]]` 超過 120 字 | 警告 |
| `deck.yml` 的 `source` 不存在 | 警告 |
| 筆記 front matter 出現版型設定 | 警告（請移到簡報） |
| 急件沒有到期日、或已經到期 | 警告 |

警告不會讓檢查失敗（結束碼仍是 0），錯誤才會。
