# 製作專案指南

這份文件說明怎麼把一個資料夾做成 Mdslide Pile 簡報。**人可以照著做,AI 也可以照著做**:規則只有這一份。

> English version: [docs/GUIDE.en.md](GUIDE.en.md)
>
> 第一次用、只想照著操作:先看 [使用手冊](MANUAL.zh-Hant.md)(操作、設定速查表、字型、顏色,可以直接複製)。

> 給 AI:請完整讀完這份文件再開始。做完後一定要執行 `node scripts/check.mjs <資料夾>`,沒有警告才算完成。最後一節是你的工作流程與驗收清單。

---

## 1. 一分鐘看懂

```
我的書庫/                         ← 書庫(可以放在硬碟或隨身碟)
├─ _site.yml                     ← 書庫設定(可省略)
├─ 01-教學/                       ← 主題
│  ├─ _topic.yml                 ← 主題設定(可省略)
│  └─ 2026-11-讀書會/              ← 專案 = 一份簡報
│     ├─ deck.yml                ← 簡報設定(建議要有)
│     ├─ 01-問題/                 ← 章節
│     │  ├─ 01-現況.md            ← 投影片
│     │  └─ 02-數據.md
│     ├─ 02-方法/
│     └─ media/                  ← 圖片、影片
└─ 02-工作/
```

- **資料夾就是結構**:書庫 → 主題 → 簡報 → 章節 → 投影片。
- **一個 `.md` 檔就是一張投影片**(也可以用 `---` 在一個檔案裡放好幾張)。
- **所有設定檔都可以省略**,只靠資料夾名稱也能播放。

開啟時可以選「整個書庫」、「一個主題」或「單一簡報」資料夾,工具會自動判斷是哪一層。

---

## 2. 資料夾與命名規則

| 規則 | 說明 | 範例 |
|---|---|---|
| 數字前綴決定順序 | 顯示時自動拿掉前綴 | `01-問題` 顯示為「問題」 |
| 日期前綴 | 當成日期,不當成順序;沒有前綴的簡報依日期新到舊排 | `2026-11-讀書會` |
| 底線 `_` 或點 `.` 開頭 | 略過,不會播放;適合放草稿 | `_草稿.md`、`_舊版/` |
| 保留資料夾 | 只放素材,不會變成章節 | `media/` `assets/` `images/` `img/` `video/` `videos/` |
| 說明文件 | 不會變成投影片 | `README.md`、`AGENTS.md` |

**命名建議**(專案和主題名稱很重要,之後可能要整份刪除或搬移):

- 主題:`01-教學`、`02-工作`,用短名詞。
- 簡報:`2026-11-讀書會-筆記系統`,日期開頭方便排序與辨識。
- 章節:`01-問題`、`02-方法`,兩位數字,留空間插入(`015-補充` 也可以)。
- 投影片:`01-現況.md`,檔名只給自己看,畫面上顯示的是內文標題。
- 避免在名稱裡使用 `/ \ : * ? " < > |`。

**自動判斷開啟的是哪一層**(依序檢查):

1. 有 `deck.yml` → 單一簡報
2. 有 `_topic.yml` → 主題
3. 有 `_site.yml` → 書庫
4. 資料夾裡直接有 `.md` → 單一簡報
5. 子資料夾有 `deck.yml` → 主題;子資料夾有 `_topic.yml` → 書庫
6. 子資料夾直接有 `.md` → 單一簡報(子資料夾是章節)
7. 其他 → 書庫

> 放在主題底下的簡報,**建議一定要有 `deck.yml`**(一行 `title: 標題` 就好),判斷最不會出錯。

## 3. 設定檔

設定檔都是 YAML。只支援常用語法:`名稱: 值`、縮排的巢狀、`- 清單`、`[a, b]`、`|` 多行文字、`#` 註解。**縮排請用空白,不要用 Tab。**

### deck.yml(一份簡報)

```yaml
mdslide: 1                     # 規則版本,目前是 1
title: 用 Markdown 做一場會動的簡報
subtitle: 2026 讀書會分享
kicker: 讀書會 · 第 12 期        # 標題頁最上方的小字
author: Toru
event: 台北讀書會
date: 2026-11-20
size: small                    # 整份用小一號的字(資料多的報告;可省略)
theme: paper                   # paper(紙張)/ ink(深色)/ slate(石板)
lang: zh-Hant                  # 自動產生文字(謝謝、大綱…)的語言:zh-Hant / en;省略時依標題等文字判斷
accent: "#b4654a"              # 沒有章節顏色時用的強調色
cover_image: media/cover.jpg   # 標題頁右側的圖(可省略)
tags: [讀書會, 筆記]
layout:
  stage: pile                  # 開場排列:pile / coverflow / carousel / helix / sphere / overview / side(對照:大圖 + 縮圖列;手機預設)
cover: true                    # false = 不要自動標題頁
section_covers: true           # false = 不要自動章節封面
end: 謝謝聆聽                   # 自動加一張結尾頁(可省略)
end_notes: 進入問答            # 結尾頁的講者備註
cover_notes: |                 # 標題頁的講者備註
  開場先停三秒。
brand:                         # 品牌(可省略)
  logo: media/logo.svg         # 內容頁頁尾左側的標誌(放在簡報資料夾內)
  footer: 公司名稱 · 內部使用    # 頁尾文字(取代章節名稱)
  font_display: Noto Serif TC  # 標題字型(只填字型名稱,電腦上要有這個字型)
  font_body: Noto Sans TC      # 內文字型
sections:                      # 只用來覆寫章節屬性;順序永遠依資料夾前綴
  - folder: 01-問題
    title: 問題:筆記越寫越亂
    subtitle: 為什麼寫了很多卻用不到
    color: "#c0674a"
    notes: 這一章大約 5 分鐘     # 自動章節封面的講者備註
  - folder: 99-附錄
    hidden: true               # 保留檔案,但不播放
```

`brand` 的字型只接受字型名稱(文字、數字、空白、`-`、`_`、`.`,可用逗號列出多個),不會下載外部字型;為了安全,不支援在簡報資料夾放自訂 CSS。

每個欄位都可以省略。沒寫的話:標題用資料夾名稱、章節顏色自動分配、主題用 `paper`、排列用 `pile`。

### _topic.yml(一個主題)

```yaml
name: 教學
description: 讀書會與內部分享
color: "#4f73a6"
order: [2026-12-年終, 2026-11-讀書會]   # 可省略,預設依前綴或日期
```

### _site.yml(整個書庫)

```yaml
title: Toru 的簡報書架
description: 一句話說明
theme: paper                    # 目錄頁的主題;電腦設成深色模式時,目錄頁自動改用 ink
topics: [02-工作, 01-教學]              # 可省略
```

## 4. 投影片怎麼寫

### 基本

就是一般的 Markdown:

```markdown
# 標題就是結論

- 第一點,**粗體**會用章節顏色強調
- 第二點,==螢光== 也可以
  - 子項目會縮小變灰
- [x] 核取方塊
- [ ] 未完成

一般段落。段落裡的單一換行會保留。
```

支援:標題、清單(有序、無序、巢狀、核取)、引言、表格、程式碼區塊、粗體、斜體、刪除線、`==螢光==`、`行內程式碼`、連結、圖片。**原始 HTML 不會生效**(會直接顯示成文字,這是為了安全)。

### 一個檔案放多張

用**單獨一行**的 `---` 分開(程式碼區塊裡的不算):

```markdown
# 第一張
---
# 第二張
```

### 講者備註

單獨一行寫 `Note:`(或 `備註:`),後面的內容只有講者視窗看得到:

```markdown
# 投影片內容

Note:
這裡提一下上週的例子。
```

### 單張設定

寫在**檔案開頭**的 front matter,影響整個檔案:

```markdown
---
layout: split-left
step: true
---
```

或寫在**每一張的開頭**,只影響那一張(用 `---` 拆張時很好用):

```markdown
<!-- layout: quote -->
<!-- color: #4f73a6 -->
```

| 設定 | 說明 |
|---|---|
| `layout` | 版型,見下一節;預設 `auto` 自動判斷 |
| `step: true` | 逐步顯示:清單、數字卡、時間軸、分欄、大綱一項一項出現 |
| `color` | 這張的強調色 |
| `background` | 背景:寫檔名是背景圖(`media/photo.jpg`),寫顏色是背景色(`"#1f3a5f"`,要加引號)。深色背景字自動變淺,淺色背景字自動變深;顏色建議用 `#色碼` 才判斷得出深淺 |
| `overlay` | 背景圖的遮罩:`auto`(預設,淡化成主題底色)/ `dark`(深色遮罩,字自動反白)/ `light`(淺色遮罩)/ `none`(不加)。照片背景適合封面、引言、大數字這類字少的張 |
| `text` | 文字顏色(通常不用設,背景深淺會自動配) |
| `fit: contain` | 媒體完整顯示,不裁切 |
| `size` | 字級:`small`(約 8 成,留白收窄,給資料多的投影片;舊寫法 `compact` 也可以)/ `normal` / `large`(約 1.15 倍)/ `xl`(約 1.3 倍)。寫在 `deck.yml` 就整份套用,某一張寫 `normal` 可以取消 |
| `font` | 這張的字型名稱,例如 `Noto Serif TC`(電腦上要有這個字型;多個用逗號分開) |
| `align` | 文字對齊:`left`(預設)/ `center` / `right` |
| `ratio` | 欄寬比例(畫面上的左:右):`split`、`split-left` 寫 `2:1`;`columns` 可以寫 `1:1:2` |
| `footer: false` | 不顯示頁尾 |
| `hidden: true` | 不播放這張 |
| `title` | 給講者視窗與總覽用的標題(預設取第一個標題) |
| `chart` / `unit` | 圖表類型與單位(chart 版型用) |

### 圖片與影片

**單獨一行**的圖片語法,就是這張投影片的主要媒體:

```markdown
![圖片說明](media/photo.jpg)
![影片說明](media/demo.mp4)
![說明](https://www.youtube.com/watch?v=影片ID)
![說明](media/photo.jpg "引號裡的文字會當成圖說")
```

- **路徑**:`media/a.jpg` 相對於「簡報資料夾」(推薦,任何章節都通用);`./a.jpg` 相對於這個 MD 檔。
- **本機格式**:圖片 jpg、png、gif、webp、svg、avif;影片 mp4、webm、mov。
- **線上影片**:YouTube、Bilibili、Google Drive(要設成「知道連結的人可檢視」)、Vimeo。貼一般分享網址即可。需要網路。
- **互動網頁**:寫法一樣,放大那張投影片時就能直接在上面操作。
  - 簡報資料夾裡的 `.html` 檔,例如 `![說明](media/demo.html)`。從倉庫(網站內建書庫)播放時,同資料夾的 CSS、JS、圖片都讀得到;從本機資料夾播放時,請做成**單一檔案**(CSS 與 JS 寫在 HTML 裡面)。
  - GitHub Pages 上的網頁,例如 `![說明](https://帳號.github.io/專案/)`。
  - CodePen 作品,例如 `![說明](https://codepen.io/帳號/pen/作品編號)`,會顯示執行結果。
  - 放大後右上角有「在新分頁開啟」。網頁在隔離的框框裡執行,碰不到你的資料夾與本網站的資料;其他網站的網頁不支援嵌入。
  - 點進網頁操作後,鍵盤會跟著進去;在網頁外面點一下,方向鍵就回到簡報。匯出的單一 HTML 檔裡,資料夾中的 `.html` 無法播放。
- 影片建議優先放線上;本機影片請壓到 1080p,單檔 100 MB 以內。
- 段落中間的圖片(不是單獨一行)會當成文字裡的小圖。
- **好幾張圖並排**:單獨一行的圖片有兩張以上,自動排成 `gallery`(2–3 張一列,4 張 2×2,5–6 張分三欄,最多 8 張)。
- **截圖標註**:在這一張開頭寫 `<!-- mark: 左 上 寬 高 標籤 -->`,在主要圖片上畫紅框加標籤;四個數字是圖片上的百分比(0–100),可以寫好幾行。標籤前加 `#色碼` 換顏色,例如 `<!-- mark: 10 40 30 20 #1e88e5 AI 給做法 -->`。不用自己算座標:**在編輯模式的預覽圖上拖曳**,就會自動插入這一行。有標註的圖會完整顯示(不裁切)。換到其他 Markdown 軟體看,標註是看不見的註解。

### 腳註

在文字旁寫 `[^1]`,再在檔案任何地方用單獨一行寫 `[^1]: 內容`。編號依引用順序自動產生,內容以小字放在投影片內容最後。引用了卻沒有定義的腳註,檢查時會提醒。

```markdown
營收成長 35%[^1]

[^1]: 2026 年第三季財報
```

### 程式碼上色

程式碼區塊標上語言就會自動上色,支援 `js`、`ts`、`python`、`json`、`bash`、`sql`(其他語言照原樣顯示)。

### 資料來源、資料時間與註腳

有引用數據時,照這三條寫,畫面會自動排成專業的註腳樣式:

1. **數字旁邊寫來源。** 以 `資料來源:`、`來源:`、`資料截至`、`註:` 或 `Source:` 開頭的段落,會自動變成頁面下方的小字註腳。
2. **時事簡報寫明資料時間。** 在 `deck.yml` 的 `kicker` 寫「資料截至 2026/11/6 收盤」,標題頁就會顯示。
3. **最後放一張「資料來源」。** 用連結清單列出所有來源,方便觀眾拍照與查證。

```markdown
## 9,943 億元

10 月外資賣超台股新台幣 9,943.16 億元,創單月紀錄。

資料來源:經濟日報,2026/11/6
```

由別的數字推算出來的值(例如由兩天收盤價相減),要在註腳寫「推算」。

## 5. 版型

`layout` 不寫就是 `auto`,規則是:

- 兩個以上的媒體 → `gallery`
- 只有一個媒體、沒有文字 → `full`
- 只有引言加一張照片 → `quote`(引言加頭像)
- 文字加媒體 → `split`
- 只有引言 → `quote`
- 第一行是很短的 `## 數字`,總共不超過 3 行 → `number`
- 其他 → `text`

| 版型 | 用途 | 寫法 |
|---|---|---|
| `text` | 一般內文 | 標題 + 清單或段落 |
| `center` | 置中強調 | 同上,內容垂直水平置中 |
| `split` | 左文右圖 | 文字 + 單獨一行的媒體 |
| `split-left` | 左圖右文 | 同上 |
| `full` | 滿版圖片或影片 | 只放媒體;若有文字,會疊在下方 |
| `quote` | 引言 | `> 引言`,下一行 `— 出處`;再加一張單獨一行的照片,就變成右側人像、邊緣淡出 |
| `number` | 大數字 | `## 68%`,下一行說明 |
| `stats` | 數字卡(2–4 張) | 清單項目寫成 `- **68%** 說明`;數值太長時字級會自動縮小,建議 8 個字以內 |
| `timeline` | 時間軸、步驟 | `- **2024** 事件`,子項目是小字;結尾加 `(now)` 標示目前 |
| `columns` | 分欄比較 | 單獨一行 `+++` 分欄;第一段只有標題時當整張標題 |
| `agenda` | 自動大綱 | 列出所有章節,不用自己寫 |
| `chart` | 圖表 | 寫一個表格:第一欄標籤,其他欄數值;`chart: bar / hbar / line`,`unit: 張`。數值可帶千分位、負號(− 或 -)、% 與單位;缺值寫 `—`、`N/A` 或留白 |
| `flow` | 流程圖 | 每一組清單是一列,項目之間自動畫箭頭。清單前單獨一行的字是這一列的標籤(整行粗體 = 強調色標籤);整個項目粗體 = 強調色方塊;項目下一行縮排的文字 = 方塊內換行;縮排的子項目 = 方塊下方的小方塊。一列建議 3–6 個 |
| `grid` | 多區塊(像簡報軟體的卡片排版) | 和 `columns` 一樣用單獨一行 `+++` 分開,區塊多時自動換行:2–3 個一列,4 個 2×2,5–6 個 3×2,7–8 個 4×2。第一段只有標題時當整張標題;區塊裡單獨一行的圖片會留在區塊裡顯示 |
| `gallery` | 多圖並排 | 標題 + 兩行以上單獨一行的圖片;`ratio: 2:1` 可以調欄寬 |
| `end` | 結尾頁 | `# 謝謝聆聽` + 聯絡方式 |
| `title`、`section` | 自動產生的標題頁與章節封面 | 通常不用手寫 |

範例:

```markdown
<!-- layout: stats -->
# 今年的成果
- **3 倍** 使用人數成長
- **12 分** 平均準備時間
- **98%** 滿意度
資料來源:2026 年內部問卷
```

```markdown
---
layout: chart
chart: bar
unit: 萬
---
# 季營收
| 季 | 2025 | 2026 |
|---|---|---|
| Q1 | 120 | 150 |
| Q2 | 135 | 180 |
```

完整示範請看 `content/00-官方範例/01-功能總覽/`,每種版型都有。

## 6. 做出好簡報的原則

這些不是語法規則,是讓簡報達到職業水準的寫法:

1. **一張只講一件事。** 標題直接寫結論(「營收成長來自新客」),不要只寫主題(「營收分析」)。
2. **清單最多 5 條,每條最多一行半。** 放不下就拆成兩張。
3. **張數依時間決定**(含自動產生的標題頁與章節封面):

   | 時間 | 建議張數 | 章數 |
   |---|---|---|
   | 5 分鐘 | 6–8 張 | 1–2 章 |
   | 10 分鐘 | 10–13 張 | 2–3 章 |
   | 15 分鐘 | 14–18 張 | 3 章 |
   | 25–30 分鐘 | 20–30 張 | 3–5 章 |

   超過 45 張檢查工具會提醒。
4. **數字要有來源。** 沒有真實資料就不要編;示意數據要明確標示「示意」。
5. **每章 3–7 張。** 章節是聽眾的路標,開場可以放一張 `agenda`。
6. **少用全文字頁。** 每 3–4 張穿插一張 `number`、`quote`、`full` 或圖表,讓節奏有變化。
7. **把細節放進備註。** 投影片給觀眾看,備註給自己看。
8. **結尾給一個行動。** 最後一張前放「下一步」或「結論」,而不只是「謝謝」。
9. **敏感主題加免責聲明。** 投資、醫療、法律相關的簡報,在結論頁寫明「不構成投資(醫療、法律)建議」。

## 7. 給 AI 的工作流程

### 收到需求時先確認

- 主題、聽眾是誰、時間多長、要放在哪個主題資料夾。
- 有沒有素材(圖片、數據、影片網址)。沒有數據時**不要捏造數字**。

### 收到資料或來源時

1. **先整理一張數字表**(只在你的工作筆記裡,不放進簡報):每個數字對應一個來源與日期。
2. 數字只能來自使用者給的資料、或你實際開啟過的來源頁面;搜尋結果的摘要不算來源。
3. 來源之間互相矛盾時,採用較原始的來源(官方公告 > 主流媒體 > 部落格),並在備註說明。
4. 推算出來的數字要標「推算」;比較的時間點不同時,要寫出時間點(例如「截至 11/4」)。

### 產生步驟

1. 決定簡報資料夾名稱:`YYYY-MM-簡短名稱`,放在對應主題底下。在倉庫裡可以用 `node scripts/new-deck.mjs <資料夾> --title "標題"` 一次建好 `deck.yml`、三個章節與起手投影片,再改寫內容。
2. 先寫 `deck.yml`:`mdslide: 1`、`title`、`subtitle`、`date`、`theme`、`kicker`(時事寫資料時間)、`cover_notes`,以及每章 `sections` 的標題、顏色與 `notes`。
3. 規劃章節與每章張數,總數依第 6 節的表格決定。
4. 每張一個檔案:`01-xxx.md`,檔案開頭需要時才加 front matter。
5. 至少使用 4 種不同版型;第一章放一張 `agenda`。
6. 每張都寫 `Note:` 講者備註(講什麼、停在哪、問觀眾什麼);引用的數字在備註寫出來源。
7. 媒體一律用 `media/` 路徑或線上網址;不要引用不存在的檔案。
8. 執行檢查(三種方式結果相同,擇一即可):

```bash
node scripts/check.mjs <簡報或書庫資料夾> --slides   # 在倉庫裡
node mdslide-check.mjs <簡報或書庫資料夾> --slides   # 書庫裡的單檔版
```

沒有命令列可用時,請使用者在網站開啟資料夾後按「✓ 檢查」,把結果貼回來。

### 版型做不到時:做一個小型 HTML 檔

內建版型與設定不夠表達時(例如流程圖、架構圖、互動試算、特殊的資訊圖表),可以在 `media/` 放一個 `.html` 檔,用 `![說明](media/xxx.html)` 單獨一行嵌入(見第 4 節「互動網頁」)。網頁在隔離的框框裡執行,碰不到使用者的資料夾。

- **先用內建版型。** 只有內建版型真的做不到才做 HTML;純文字、清單、表格、一般圖表都不需要。
- **單一檔案。** CSS 與 JavaScript 都寫在 HTML 裡,不引用其他檔案。
- **不連外部網路。** 不載入外部字型、函式庫或圖片,離線也要能顯示。
- **配合 16:9。** 版面以 1280×720 為準,用相對單位,字級至少 20px;背景透明或配合簡報主題的顏色。
- **不存資料。** 不用 localStorage、Cookie,不送出表單到任何網址。
- **檔名清楚。** 例如 `media/flow-導入步驟.html`;在講者備註寫這張要怎麼操作。
- **知道限制。** 在牌堆和縮圖裡只會顯示佔位圖,放大那張才會執行;匯出的單一 HTML 檔裡不能播放。所以重要的結論要寫在投影片文字或備註裡,不要只放在 HTML 裡。

### 交付前的驗收清單

- [ ] 檢查結果顯示「✓ 沒有發現問題」
- [ ] 每張投影片的標題是一句結論
- [ ] 沒有超過 5 條的清單、沒有捏造的數字
- [ ] 每章有標題與顏色,章節數與張數符合時間長度
- [ ] 沒有內容超出畫面(編輯模式的預覽與播放器裡的「檢查」會警告;太多就拆張或用 `size: small`)
- [ ] 沒有空白投影片(只有設定、沒有內容的張數,檢查工具會警告)
- [ ] 每張都有講者備註(`check.mjs` 會顯示備註覆蓋率)
- [ ] 有數字的投影片都有「資料來源:」註腳,最後有一張資料來源頁
- [ ] 時事簡報的 `kicker` 寫了資料時間;敏感主題有免責聲明
- [ ] 媒體路徑正確,線上影片網址可以公開觀看
- [ ] 自製的 HTML 檔是單一檔案、不連外部網路

### 可以直接使用的提示詞

```text
請先完整閱讀 製作專案指南.md。
幫我在「<主題資料夾>」底下做一份簡報:
- 主題:<主題>
- 聽眾:<聽眾>
- 長度:<分鐘> 分鐘
- 素材:<數據、圖片、影片網址,或「沒有」>
依照指南第 7 節的步驟產生資料夾與檔案,完成後執行 check.mjs 並回報結果。
```

## 8. 常見問題

- **畫面上的順序不對?** 檢查數字前綴。前綴是依數字大小排序(`2-` 在 `10-` 前面),但建議統一用兩位數(`02-`),在檔案總管裡也會排得一樣。檢查工具會警告同一層的前綴重複或位數混用。
- **可以直接在網站上改內容嗎?** 可以。放大投影片後按 `E`(或工具列的「編輯」),左邊改 Markdown、右邊即時看結果,`Ctrl+S` 儲存回你資料夾裡的檔案(需要 Chrome / Edge 開啟的本機資料夾,第一次存檔瀏覽器會問一次是否允許寫入)。上方的工具列可以選版型、插入標題、清單、圖片或影片、分欄、新的一張與備註,不用記語法;「外觀 ▾」面板可以用選的設定字級、背景色或背景圖、遮罩、強調色、文字色、字型、對齊、欄寬比例、逐步顯示、隱藏與頁尾(會寫成這一張開頭的設定註解);`‹` `›`(或 `Alt+PageUp` / `Alt+PageDown`)直接換到上一張、下一張,換到別的檔案前會自動存檔。
  - 工具列還有「+ 新增一張」(自動接續編號)與「封存」(把檔案搬到簡報資料夾下的 `_封存/`,**不會真的刪掉**,之後可以自己搬回來)。
  - 自動產生的封面與章節頁沒有自己的檔案,按 `E` 會改成編輯 `deck.yml`。
  - 編輯期間如果檔案被其他程式(例如編輯器)改過,存檔前會先問你要用哪一個版本,不會直接覆蓋。
  - 講者視窗(`S`)也能直接改這一張的備註,存檔後畫面會自動更新。
  - 其他瀏覽器與網站內建書庫不能存檔:「儲存」會變成下載修改後的檔案;內建書庫另外提供「在 GitHub 上編輯」。
- **改了檔案,畫面要怎麼更新?** 用 Chrome / Edge 開啟的資料夾會自動更新(約 1.5 秒內),也可以按 `R`。其他瀏覽器請重新選擇資料夾。
- **某張沒出現?** 檔名是不是 `_` 開頭?front matter 有沒有 `hidden: true`?
- **圖片顯示「找不到素材」?** 路徑是相對於簡報資料夾,例如 `media/a.jpg`,大小寫也要一致。
- **設定檔沒作用?** 用空白縮排、冒號後面要有空格;按網站的「✓ 檢查」會指出第幾行有問題。
- **隨身碟換了一台電腦?** 用 Chrome / Edge 開啟網站,再選一次資料夾即可。
- **要寄給別人,或在沒有網路的電腦上報告?** 在播放畫面按右上角的「匯出」,會下載一個 `.html` 檔:程式、樣式、內容與圖片都在裡面,雙擊就能離線播放(牌堆動畫、講者視窗都能用)。本機影片與音訊預設不放進去(檔案會很大),可以在對話框勾選;YouTube 等線上影片仍需要網路。
- **圖表被裁掉一部分?** 播放時點一下圖片就能看完整的原圖。如果希望投影片上就完整顯示,在那張的開頭設定加上 `fit: contain`(見第 5 節),適合圖表、截圖這類不能裁切的圖。
- **上台時想圈重點?** 放大投影片後按 `D`(或工具列的 ✎)打開畫筆。預設是雷射筆,畫的線停筆後會一起淡出;也可以換成畫筆、螢光筆、橡皮擦。講者視窗(`S`)裡也能畫,觀眾畫面會同步出現。
- **想把簡報給沒到現場的人看?** 按 `M`(或工具列的「閱讀」)進入閱讀模式:整份簡報排成一頁往下捲,每張下面附講者備註。這時的網址結尾是 `/read`,直接分享這個網址即可;按「列印講義」可以印成附備註的 A4 講義。所以講者備註寫得完整一點,閱讀的人也看得懂。
